# 自动推送设置

把扫描变成定时任务(scheduled task),按用户选的频率自动跑,有新开岗推送到用户的 Claude 通知(含手机推送)。

---

## 一 · 前置确认

定时任务用 `create_trigger` 类工具创建(claude-code-remote MCP,工具名如 `mcp__claude-code-remote__create_trigger`,可能需要先用 ToolSearch 加载)。**先确认工具可用再向用户承诺**。不可用时(本地会话/无权限)不要硬试,走第四节的降级方案。

## 二 · 用户的两个选择

**推送范围**(方向确定后问):

- A. 只推荐方向相关公司 — 用方向评估选出的公司集合(通常 10-20 家),推送更准
- B. 两大类全部 — OEM + 供应商全监测(约 40 家),不漏但可能有噪音

**频率**(默认推荐"每周一三五"):

| 选项 | cron(UTC,北京时间早 8 点推送) | 报告窗口 |
|---|---|---|
| 每天一次 | `0 0 * * *` | 48 小时内新发布 |
| 每周一三五 | `0 0 * * 1,3,5` | 4 天内新发布 |
| 每周一次(周一) | `0 0 * * 1` | 8 天内新发布 |

秋招季(8-10 月)主动建议选"每天":这个季节 HC 关得快,晚两天知道可能就错过截止。其他季节一三五足够。

cron 用 UTC 表达。若用户要求其他推送时刻,按 北京时间 − 8 小时 换算;跨天时记得同步移动星期字段。

## 三 · 创建定时任务

调用 create_trigger,参数要点:

- `name`:`开岗雷达 · {学生名或方向} · {频率}`
- `cron_expression`:按上表
- `notifications`:`{"push": true}`(推送到手机;用户要邮件就加 `"email": true`)
- `prompt`:**必须完全自包含**。定时任务每次在全新会话里运行,没有本次对话的任何记忆,也读不到本次会话的文件。学生的方向、公司清单、URL、判定规则、输出格式全部要写进 prompt 里。

### prompt 模板

按下面模板填充(『』内是要替换的内容),公司清单从 [channels.md](channels.md) 按用户选的范围摘出,每家一行"公司名(分类): 校招/实习URL":

```
你是"车企开岗雷达"。为一位求职车企 HMI 设计岗的学生做开岗扫描,今天是本次运行日。

学生画像:『方向:交互/视觉/3D/系统框架/AI语音;届次:202X届;找:实习/校招;城市偏好:XX』
岗位关键词:『按方向映射的关键词,如 HMI、交互、UX、体验设计』+ 设计

监测清单(优先 WebFetch 官方入口;JS 渲染抓不到列表或访问失败时,用 WebSearch 兜底:
site:nowcoder.com / site:shixiseng.com / "公司名 202X届 校园招聘 就业网" / 公众号文章。
单家最多 3 次尝试,查不到标"未能确认"):
『公司名(OEM-新势力): https://...
公司名(供应商-国内): https://...
…』

判定规则:
- 发布时间在『48小时/4天/8天』内的匹配岗位 → 新开岗
- 投递截止在 7 天内的 → 无论发布时间,标 ⏰ 进推送
- 在招但发布时间未知的存量岗位,只挑与学生方向高匹配的至多 2 条
- 不虚构岗位和时间;查不到如实标注;二手信息注明来源

输出(这是最终推送内容,直接给学生看,不要写扫描过程):
🚗 开岗雷达 X月X日
【新开岗】公司 · 岗位(城市)— 截止日期 → 投递链接
【⏰ 即将截止】…
【窗口提醒】只在秋招/春招窗口切换等关键节点写一句
没有新开岗时:一句话确认"今日扫描X家,无新开岗",不要编内容。
```

创建成功后告诉用户:推送会出现在 Claude 通知里(手机 App 需开启通知);随时回来说"暂停推送/改频率/换方向"就能调整(对应 update_trigger / delete_trigger);目前手机端看不到定时任务的管理列表,管理要在桌面端对话里做。

## 四 · 降级方案(trigger 工具不可用时)

如实告诉用户自动推送在当前会话开不了,给两个替代:

1. 保存一份"扫描指令"文本给用户(即上面 prompt 模板填充后的内容),让用户每周把它粘贴到新对话里手动跑——效果一样,只是要自己记得
2. 建议用户在 Claude 桌面版/云端 Cowork 会话里重新运行本 skill,那里通常可以创建定时任务

不要静默跳过推送环节——推送是这个 skill 的核心承诺,开不了要明确说。
